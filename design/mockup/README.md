# App 设计稿（高保真原型）

这个目录是**设计稿的唯一真源**。改设计 → 改 `build.py` → 重新生成 HTML → 重新出图。

```bash
python design/mockup/build.py     # 由 build.py 生成 6 个界面 HTML + 总览
python design/mockup/shoot.py     # 用 Chrome 截图（CDP 精确控制视口）
python design/mockup/shoot.py 03  # 只重出某一屏
```

产物在 `screenshots/`。

## 为什么是 HTML/CSS 而不是图片

- **像素级准确**：出来的图就是浏览器真实渲染的，不会有"设计图和实现对不上"
- **可以直接变成代码**：`base.css` 里的 class 可以原样搬进 `src/companion_ever/web/`
- **改一处，全屏同步**：`build.py` 改一行 → 重新出图

## 截图工具的坑（已解决）

`chrome --headless --screenshot --window-size=402,874` **在 Windows 上不可靠**：
Chrome 有最小窗口宽度（实测 ~490px），`--window-size` 给小了不生效，截出来的图右边会被裁掉。

所以 `shoot.py` 走 **Chrome DevTools Protocol**：
`Emulation.setDeviceMetricsOverride` 精确设定视口（402×874 @2x），和真机一致。
另外注意 DevTools 的 WS 连接**不能带 Origin 头**（`websockets.connect(..., origin=None)`）。

## 信息架构

**底部三个 Tab**（对齐微信的手感，但内容是这个产品自己的）：

```
┌─ 消息 ────┬─ 通讯录 ──┬─ 我 ────┐
│ 聊天列表   │  角色列表  │  设置   │
└───────────┴───────────┴────────┘
        ↓ 点进去               ↓
   会话页 ──右上角头像──→ 角色资料页 ──→ 她的记忆（某个角色的记忆）
```

### 为什么没有「记忆」Tab

**不同 AI 伴侣的记忆是不同的**，混在一个 Tab 里就分不清是谁的。
所以记忆挂在**角色资料页**下面 —— 进去就明确知道"这是柳如烟的记忆"。

### 为什么没有「结束会话」按钮

按之前商量的：对话**每 2 小时自动记录一次**（`COMPANION_IDLE_MINUTES`）。
所以界面上的表达是：

- **上次记录：3 天前**（告诉她记忆有多新）
- **手动记一次**（想现在记就点一下）
- 不再有"结束会话"这个说法 —— 记录是后台行为，不该打断对话

| 屏 | 层级 | 文件 | 说明 |
|---|---|---|---|
| 消息 | Tab | `01-messages.html` | 每个角色一行：头像 + 名字 + 最后一句 + 时间 + 未读角标。顶部搜索，右上「＋」新建 |
| 通讯录 | Tab | `02-contacts.html` | 上半「角色」、下半「功能」（新建角色 / 群聊） |
| 我 | Tab | `04-me.html` | 个人信息 + 设置。**文案保持多伴侣中立**（不写"和某某在一起 N 天"） |
| 会话 | 子页 | `05-conversation.html` | 现有聊天界面：思考折叠块、「回到最新」悬浮按钮、Markdown 渲染。右上角头像 → 角色资料 |
| 角色资料 | 子页 | `06-profile.html` | 大头像 + 设定 + 统计 + 入口 + **记忆记录区（上次记录 / 手动记一次）** |
| 她的记忆 | 子页 | `03-memory.html` | 标题带角色名（「柳如烟的记忆」），统计条 + 类型筛选 + 记忆卡片 |

## 图 → 代码：落地映射

### 纯前端改动（不动后端）

| 屏 | 需要什么 |
|---|---|
| 消息 | 新增 Tab 栏 + 聊天列表页；数据来自每个角色的 `/history?limit=1` |
| 通讯录 | 角色列表来自 `/api/users`（已返回 `personas` 数组）；「新建角色」需要新接口 |
| 我 | 把现有抽屉里的内容拆出来变成独立页；「服务器地址」「自动记录间隔」是新增的本地配置 |
| 会话 | **已有**，只加顶栏角色头像入口 |
| 角色资料 | 统计数字来自 `/api/persona/{u}/{p}`（已有 `note_count` / `message_count` / `session_count`）；「上次记录」需要知道最近一次抽取时间 |
| 她的记忆 | 数据来自 `/api/persona/{u}/{p}/notes`（已有）；重要度字段已有 |

### 需要后端加的东西（很少）

1. `POST /api/persona/{u}/personas` —— 新建角色（CLI 的 `setup` 只能建用户+第一个角色）
2. 每个角色的"最后一条消息" —— 前端拿（每个角色拉一次 `/history?limit=1`）或后端加聚合接口
3. **"上次记录"时间** —— 需要暴露最近一次抽取完成的时间（现在的 `session_close` 报告里没有这个字段）

### 打包成 App 前还缺的（前端侧）

1. **服务器地址可配置** —— 现在请求都是 `location.host` 相对路径
2. **首次启动引导** —— 现在必须先在电脑上跑 `companion-cli setup`
3. **CORS** —— App 的源是 `capacitor://localhost`，跨域要放行
