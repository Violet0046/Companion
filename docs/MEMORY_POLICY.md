# 记忆规则与数据契约

## 笔记与情境

`note.kind` 只有两种：`episode` 表示具体经历或有意义的共同互动；`fact` 表示有明确依据的长期事实、偏好或约定。重要性不决定 kind。旧 `note.type` 及类型加分已删除，角色设定存于 `persona_definition`。

独立字段 `reality` 表示内容的现实情境：

| 值 | 含义 |
|---|---|
| `user_report` | 用户自述的现实信息，不等于外部核实 |
| `shared_fiction` | 双方明确建立的共同想象或角色扮演 |
| `uncertain` | 情境不足以确定；摘要展示时保留“待核实” |

旧库迁移统一将旧笔记标为 uncertain，不猜测现实/虚构。新整理可在用户明确证实时确认情境；不会为了消除界面标记而批量认定为现实。

## 已确认的保存边界

| 内容 | 处理 |
|---|---|
| 条件承诺 | 随相关经历保留触发条件和兑现未知状态，不改写成无条件欠账 |
| 有进展的现实事件 | 保存事件时间、截至状态和来源；相关话题才召回 |
| 随口吐槽的日常小事 | 默认留在原始聊天；明确要求记住或产生持续影响时另议 |
| 当天疲惫等短期状态 | 由近期聊天承接，不建立长期画像或额外状态抽取链 |
| 明确建立的共同想象经历 | 可以长期保存，标注 shared_fiction，不冒充现实经历 |
| 一次临时选择 | 不升级长期偏好；是否并入经历取决于整个片段的价值 |

保存资格与本轮召回资格分开；允许保存不表示每次都要提起。结构校验只能核对可验证约束，不能证明模型完全理解原话。

## 整理与原子写入

输入包含 `new_message_ids`、只读参考前文和已有候选。每条用户新消息必须被建议引用或在 skipped 中解释跳过；每条建议必须引用本批用户消息的非空、连续逐字原文。助手发言不能替代用户证据，跨角色/跨范围引用被拒绝。

记忆图允许模型用 search_notes 主动核对重复/关联，或用 get_note_context 读取完整笔记、证据及一跳关系；授权范围由服务端绑定，工具没有写入能力。新检索到的候选加入同一版本快照与最终校验。已有笔记而预取为空时，保存前必须先检索；空候选不能证明不存在旧记忆。调用预算内仍无法确认同一性时不强行合并。词法检索和模型判断不能保证语义去重。

| action | 语义 |
|---|---|
| `create` | 新增笔记；明确相同事实可复用已有 ID 并补证据 |
| `append` | 仅 episode，同一经历的补充/纠正；保留修改前版本 |
| `confirm` | 仅 fact，正文与目标一致，只补证据；可确认旧 uncertain 情境 |
| `revise` | 仅 fact，新建事实版本并自动建立 supersedes，保留旧事实 |

事实精确去重考虑当前用户/角色、正文、情境和事件时间，排除归档及已被取代事实；不进行语义合并，不修改旧 importance。经历按 ID 区分，同文可代表不同事件。

`event_time` 是事情发生的 ISO 日期/时间，未知则 null；`time_basis` 解释依据。created_at/updated_at 是存储时间。每次写入重新核对候选快照、来源、归属和执行 token；任一条目不合法，整批回滚且进度不推进。

只有年/月等时间精度时不补造日期，event_time 留 null，已知精度留在 content/time_basis；模型错误填写年份时仍须纠错通过才能写入。明确建立的长期/周期性约定可以是 fact：记录的是约定存在，不能声称活动已经履行。一次性计划和条件承诺继续保留经历、条件及履行未知状态。

## 关系

| 关系 | 方向 |
|---|---|
| `supports` | 经历 → 事实 |
| `continues` | 新经历 → 前序经历 |
| `supersedes` | 新事实 → 旧事实 |

方向统一定义在 `memory/relations.py`。端点须同用户/角色且符合 kind、情境约束；事实替代允许明确纠正旧 uncertain 情境。数据库与仓库检查未知类型、自关联、重复和环路。未确认的事件归属只写 uncertainties，不创建“可能关联”的边。同一经历补充用 append，不额外建立自关联。

## 用户画像与关系概况

两个摘要只消费 fact 操作，输入是上次摘要、未消费操作及受影响/仍被引用的有效事实。操作记录在事实写入事务内产生，包含增删改、归档/恢复、替代与证据变化；硬删除仍保留 before 供撤回解释，不把已删内容当当前依据。

送入模型前按 fact 合并同一连续操作窗口的最早 before 与最终 after，去掉证据/元数据及净变化为零的操作，替代关系按边的增删净变化表达。实质变化计数以不同 fact 为单位；原始流水不删除、不改写。仅有非实质变化且旧摘要仍通过当前事实校验时，直接复用并原子推进操作游标。模型输入仍只含相关有效 fact，不重送全量事实。

模型输入的 current_facts 只给正文和元数据；citations.quote 必须逐字引用对应 content。原始聊天证据仍在 note_evidence，操作依据仍在 changes。每项结论保留 note ID、逐字引用、revision 和 reality，不能把关于角色的事实转移为用户画像。

两个摘要整体替换，不使用列表并集、静默截断或关系进度只能上涨的合并规则。操作游标与摘要同事务提交；来源变化或块被其他操作修改时拒绝旧结果。仅证据变化且原摘要仍有效，或已经没有可用事实时，可直接更新/清空而不调用模型。

聊天持续注入 checkpoint 中上一次成功提交的用户画像和关系概况。有未消费操作、任务排队/运行或更新失败时，继续使用该版本；新批次成功提交后整体替换，不因等待同步而撤下两份摘要。current/stale 只说明后台同步进度，不控制是否注入。首次尚无成功摘要时不注入未迁移的旧格式；成功提交的空摘要正常清空对应上下文。

提示词明确摘要可能滞后，用户最新明确陈述及当前有效事实优先，不能用旧摘要否定用户的更正。因此更新期间可能短暂保留旧结论，由近期聊天和有效笔记补充变化；生成新摘要时仍严格校验引用、现实情境和原子提交。用户画像和关系概况不会改写角色基础设定，也不会反写成 note。

## 召回与常驻

统一入口为 `RetrievalService.search(..., MemorySearch(...))`，聊天和 consolidation 共用。当前使用 FTS5、中文短词 LIKE 与有限关系扩展，没有向量或语义重排。

候选来自当前 query、显式 context_query 和 seed；只有 consolidation 可加入少量近期笔记。没有入口返回空结果，不全图遍历。最多两跳、64 个节点；过滤归档、范围、kind、被取代事实和重复占位，结果带原因、路径、警告与 truncated。有限扩展不保证找到整段历史的最终状态。

`pinned` 按单条 note 常驻，最多取 8 条有效笔记；不使用类别级强制注入。评分不等于置信概率，strength 目前只影响关系遍历优先级。异义改述和指代可能找不到词法入口，见 [评测](MEMORY_EVALUATION.md) 与 [待 review 项](../REVIEW_NOTES.md)。
